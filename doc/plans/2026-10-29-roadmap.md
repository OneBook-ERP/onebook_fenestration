# OneBook Fenestration: Build Roadmap

P0+P1 (see [context.md](../context.md) §7) spans several independent subsystems, so it is split into plans. Each plan ships working, tested software on its own. A plan is written in full only when the previous one is done, so each one benefits from Hilux data and earlier learnings.

| # | Plan | Delivers | Depends on | Status |
|---|---|---|---|---|
| 1 | [Engine core + DXF section analyzer](2026-10-29-plan-1-engine-core.md) | Pure-Python `engine/` package. Design tree → members, cuts, hardware, glass, weights, validation issues. DXF → section properties. Golden tests reproduce EvA W01/W02. | none | Done (merged to version-16) |
| 2 | [Masters + Series Studio backend](2026-10-30-plan-2-masters-and-api.md) | Doctypes: Profile Series, Series Version, Profile (DXF upload uses Plan 1's analyzer), Member/Hardware/Validation Rule, Glass Spec, Finish. Snapshot builder (DB → `SeriesSnapshot`). Excel import. Whitelisted `compute_design` API. Window Design + Fenestration Project doctypes. | 1 | Written |
| 3 | Vue SPA shell + Window Designer | `/fenestration` SPA (Vue 3 + TS + frappe-ui + Pinia). Project list and workspace, design cards, designer (tree editing, SVG canvas, property accordion, live results through the Plan 2 API), SVG snapshot saved on design. | 2 | Outline |
| 4 | Pricing + quote documents | Price Structure (ordered cost heads, calculation types, `#TOKEN` vars, as in EvA), price lists through ERPNext Item Price. Quotation creation. Print formats: Quotation, Elevation, Estimate Confirmation (with sign-off). | 2, 3 | Outline |
| 5 | Production outputs | Assembly summary and detail reports; 1D cutting optimizer (multiple bar lengths, 10 mm kerf, rest vs waste, wastage summary); SO → BOM/WO handoff (after D6). | 1, 2 | Outline |

## Placeholder data until Hilux sends real files

- **Series numbers:** CS400 deductions and hardware formulas reverse-engineered from the EvA PDFs (context.md §3; full set in Plan 1 fixtures). They are golden-tested against W01 and W02.
- **Profile shapes:** `doc/flush cap.dxf` (public CADdetails file: "20178 Deep Flush Cap", inches, one hollow chamber; 154.3 × 48.0 mm, area 1412.0 mm², 3.812 kg/m). It is used to test the DXF analyzer.
  - Its layer table lists a full window system (20125 Frame, 20130 Std Sash, 20139 Fixed Casement Frame, 20133 Track Cover, reinforcements). If the full source DWG/DXF can be downloaded from the same public CAD library, it gives frame, sash and bead placeholders for the designer's section and 3D views.
- When Hilux DXFs arrive, they replace the placeholders through the Plan 2 import. No code changes, because rules and shapes are data (D3).

## Open decisions that block later plans (not Plans 1–3)

- D5 tenancy: blocks dealer onboarding (after Plan 5).
- D6 window-as-Item/BOM: blocks Plan 5's SO → WO handoff.
- D8 billing area: Plan 4 needs a setting; default to frame size, the way EvA does.
